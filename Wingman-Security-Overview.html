Part A · For customers

Five overlapping security layers

Wingman uses defence-in-depth: your data stays protected even if any single layer is bypassed.

01

Infrastructure

  • Runs on a dedicated, private server — not a shared, multi-tenant platform.
  • The application listens only on the server's internal interface; it is never directly reachable from the internet. All traffic passes through a hardened reverse proxy.
  • A firewall limits inbound access to essential ports only, and an intrusion-prevention service blocks repeated malicious login attempts.
02

Network & transport

  • All web traffic is encrypted in transit with HTTPS (TLS 1.2 / 1.3) and automatically renewed certificates.
  • Messages exchanged over WhatsApp reach Wingman over encrypted channels.
03

Access & authentication

  • One-time-passcode sign-in: a six-digit code that expires in five minutes, allows five attempts, and can be used only once.
  • Sessions use cryptographically random 256-bit tokens that expire and can be revoked — sent in request headers, not cookies, which reduces cross-site request risk.
  • Strict per-user isolation — no customer can reach another customer's data.
  • Administrative functions are password-protected and kept separate from customer access.
04

Data encryption at rest

  • Sensitive stored credentials are encrypted with AES-256-GCM — authenticated encryption with a unique key per value, so any tampering is detected.
  • Encryption keys derive from a secret held only in the secured server environment — never in source code or version control.
  • Encrypted at rest: saved third-party passwords (credential vault), health-wearable tokens, work / HRMS integration secrets, and email-mailbox passwords.
05

AI-safety

  • Human approval before critical actions: Wingman shows exactly what it will do — recipient, content, amount — and waits for an explicit "yes" before sending, paying, or deleting.
  • Configurable autonomy: act automatically on routine items, or confirm everything.
  • The AI never sees stored passwords — they are decrypted only by server-side automation and are never exposed to the model or returned in a reply.
  • A full audit trail records every action — requested or proactive — which the user can review at any time.

Part A · For customers

Privacy & compliance

Never sold

Customer data is never sold to anyone.

Not used to train AI

Message content is processed to produce replies and is not used to train AI models.

Google Limited Use

Google data follows the Google API Services User Data Policy — used only for features you request, never for advertising.

You stay in control

Disconnect Google anytime (which removes stored tokens), and request full deletion of your account and data whenever you want.

Ready to share

Key assurances for customers

Eight lines you can give a customer directly.

  • All data is encrypted in transit (HTTPS / TLS).
  • Sensitive credentials are encrypted at rest with AES-256-GCM.
  • Runs on dedicated, firewalled, private infrastructure.
  • One-time-code login, expiring sessions, strict per-user isolation.
  • Explicit approval before any sensitive action, with a full audit trail.
  • The AI never sees your saved passwords.
  • Your data is never sold or used to train AI models.
  • Disconnect integrations or delete your data at any time.
